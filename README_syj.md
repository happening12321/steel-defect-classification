## 1. 프로젝트 개요

### 1.1 프로젝트 소개

**프로젝트 배경**
: 철강은 여러 산업에서 공통적으로 사용된다. 광범위한 응용 분야를 가지고 있기 떄문에 엄격한 품질 요구사항을 충족하는 것이 중요하다. 강철 표면의 결함은 제조 단계에서 강철 표면서로    다른 기계와 접촉함으로써 발생하는 경향이 있는 변형 성향 때문에 산업계에서 항상 어려운 문제로 여겨져 왔다. 전통적인 방법으로 인간 전문가가 수동으로 검색하였지만 이는 시간이 많이 소요되고, 부정확하다. 
이를 머신러닝 모델링화하여 각 데이터 특징들이 강철 표면 결함 유형을 이해, 예측, 유형분류를 하는 것은 정확하고 효율적인 예측을 통해 철강의 품질 문제 방지와 사전 예방을 위한 유지보수를 촉진할 수 있다. 


**프로젝트 목표**
: 강판 결함 1,941건의 위치·크기·모양·밝기·강판 정보 27개 변수로 결함을 7가지 유형 중 하나로 분류하는 모델을 만들고 유형분류의 정확도와 불균형 처리 방법에 따른 모델링 성능 변화를 
  비교한다.


- 예측 대상(Target)과 목표를 정의합니다.
- 프로젝트에서 중요하게 고려한 평가 지표를 설명합니다.
- 불균형 데이터 처리 전후 모델의 성능 차이를 비교합니다.

### 1.2 프로젝트 정보

| 항목 | 내용 |
|---|---|
| 프로젝트 기간 | 2026.10.13 ~ 2026.10.19  |

| 주요 기술 | Python, pandas, NumPy, scikit-learn, LightGBM, CatBoost, SciPy, Matplotlib, Streamlit |

### 1.3 주요 성과

- **모델 성능:** 
: 최종 모델(LightGBM + Extra Trees)의 테스트 Macro F1 0.8349, Accuracy 0.8201 달성

- **불균형 처리:** 
: 클래스별 예측 확률 보정을 통해 동일 테스트 데이터의 Macro F1 0.8264 → 0.8349 개선

- **주요 인사이트:**
: 강종과 결함 유형 간 강한 연관성을 확인했으며, Bumps와 Other_Faults 간 혼동이 전체 오분류의 47.1%를 차지했다. 순열 변수 중요도 분석에서는 Length_of_Conveyer, Steel_Type, 
: Steel_Plate_Thickness가 주요 변수로 나타났다.

### 5.2 데이터 특징

- 주요 Feature와 데이터 특성
: 결함 영역의 위치(X·Y 좌표 최소·최대), 크기(Pixels_Areas, X·Y_Perimeter), 밝기(Sum·Minimum·Maximum_of_Luminosity), 형상 지표(Edges_Index, Empty_Index, Square_Index, 
: Orientation_Index 등), 변환 변수(LogOfAreas, Log_X·Log_Y_Index, SigmoidOfAreas), 강판 정보(Steel_Type, Steel_Plate_Thickness, Length_of_Conveyer)

- 분석 시 고려해야 할 데이터 특성
**이상치 및 분포**: IQR 1.5배 기준 이상치 후보 비율이 Sum_of_Luminosity 20.6%, Pixels_Areas 20.4%, Outside_X_Index 19.1%, X_Perimeter 18.1%로 높게 나타났다. 해당 값들은 실제 결함 특성을 반영할 가능성이 있으므로 제거하지 않았다. 반면 LogOfAreas(0.3%)와 Log_Y_Index(0.2%)는 이상치 후보 비율이 상대적으로 낮았다.

- **변수 간 범위 차이**: Y 좌표는 최대 약 1,300만인 반면 일부 형상 지표는 0~1 범위로 변수 간 값의 크기 차이가 크다. 최종 모델은 변수의 스케일에 상대적으로 영향을 적게 받는 트리 기반 모델을 사용하므로 별도의 스케일링은 적용하지 않았다.

- **강종과 결함 유형의 연관성**: 카이제곱 검정 결과 강종과 결함 유형 간 유의한 연관성이 확인되었다(p < 0.001, Cramér's V = 0.586). 결함 유형별 강종 분포에 차이가 나타났다. K_Scatch(390/391)와 Stains(71/72)는 대부분 A400에서, Z_Scratch(172/190)는 주로 A300에서 발생한다.

| K_Scatch | 20.1% |
| Z_Scratch | 9.8% |
| Pastry | 8.1% |
| Stains | 3.7% |

**평가 지표**: 클래스 불균형으로 인한 Accuracy의 한계를 보완하기 위해 Macro F1을 주요 평가 지표로 선정.
- **데이터 분할**: 클래스 비율을 유지하는 층화 분할을 적용. (테스트 389건 중 Stains 14건, Dirtiness 11건)
- **불균형 처리**: Baseline(Gradient Boosting)에서 Pastry(Recall 0.594)와 Dirtiness(Recall 0.636)의 재현율이 상대적으로 낮게 나타나 이를 보완하기 위해 클래스 가중치    
                 튜닝과 클래스별 예측 확률 보정을 시도.
- **평가 시 주의사항**: 소수 클래스는 테스트 표본이 적어 1~2건의 오분류에도 지표가 크게 변할 수 있으므로 최종 모델의 Macro F1에 대한 부트스트랩 95% 신뢰구간을 함께 확인했다.

## 6. 데이터 분석 및 전처리

### 6.1 탐색적 데이터 분석 (EDA)

**주요 분석 내용**

- 데이터 구조 및 변수 유형 확인
| 항목 | 내용 |
|---|---|
| 데이터 타입 | int64 21개, float64 13개, 문자형(object) 0개 |
| 정렬 상태 | 앞 5행은 모두 Pastry, 뒤 5행은 모두 Other_Faults |
| 숫자 범위 | Y_Minimum 최댓값 약 1,299만, 지표 변수는 0~1 |
| 평균과 중앙값 | Pixels_Areas 평균 1,894, 중앙값 174 |

변수 유형 분류
| 구분 | 변수 묶음 | 변수 | 개수 |
|---|---|---|---|
| 수치형 (입력) | 위치 | X_Minimum, X_Maximum, Y_Minimum, Y_Maximum, Edges_Index | 5 |
| 수치형 (입력) | 크기 | Pixels_Areas, X_Perimeter, Y_Perimeter, Outside_X_Index | 4 |
| 수치형 (입력) | 면적·축 변환값 | LogOfAreas, Log_X_Index, Log_Y_Index, SigmoidOfAreas | 4 |
| 수치형 (입력) | 밝기 | Sum_of_Luminosity, Minimum_of_Luminosity, Maximum_of_Luminosity, Luminosity_Index | 4 |
| 수치형 (입력) | 형상 | Empty_Index, Square_Index, Edges_X_Index, Edges_Y_Index, Outside_Global_Index, Orientation_Index | 6 |
| 수치형 (입력) | 강판·공정 | Steel_Plate_Thickness, Length_of_Conveyer | 2 |
| 범주형 (입력) | 강종 | TypeOfSteel_A300, TypeOfSteel_A400 | 2 |
| 범주형 (정답) | 결함 유형 | Pastry, Z_Scratch, K_Scatch, Stains, Dirtiness, Bumps, Other_Faults | 7 |

- 결측치 및 중복 데이터 확인
: 의미론적 중복행 
->같은 결함으로 판단. 중복행 처리 후 모델링 재진행 -> 성능 저하로 인해 중복행으로 처리하지 않기로 결정.
: 1776–1777행이 중복행으로 보이는 이유
-> 불일치한 두 열(Edges_Index, Length_of_Conveyer)을 보면 사실상 위치 차이
-> Edges_Index는 x 위치와 컨베이어 폭에서 바로 계산되는 파생값입니다.오른쪽 가장자리까지의 거리로 계산하면 숫자가 정확히 맞습니다.
• 1776행: 2 × (1360 − 1021) / 1360 = 0.4985
• 1777행: 2 × (1358 − 1015) / 1358 = 0.5052
-> 따라서 독립적으로 측정된 값이 다른 것은 두 가지. -> X 좌표가 6픽셀 밀림
: Length_of_Conveyer가 2 차이
: Length_of_Conveyer는 앞뒤 행에서도 1364, 1362, 1360, 1358, 1360, 1356처럼 행마다 조금씩 흔들리는 측정값으로, 2 차이는 측정 잡음 수준입니다.반대로 다음 값들은 모두 같다.
- Y 좌표 (28972–28984), 상자 크기 (19×12), 면적과 둘레, 밝기 합계 13,352, 최소·최대 밝기, 강종과 두께, 나머지 형상 지표 전부

- 주요 변수의 분포 확인
: 면적·둘레·밝기 합은 오른쪽 꼬리가 길며, 로그 변환 변수에서는 IQR 후보 비율이 작다. 이 결과는 전체 
: 1,941건의 기술통계다. Y 좌표와 비율 지표의 범위 차이가 크고 일부 지표에는 음수가 포함된다.
 
- Target 클래스 분포 분석
: 전체 원본에서 Other_Faults·Bumps·K_Scatch 세 유형이 약 75%를 차지한다. 

- 변수 간 관계 분석
: 정의상 강하게 연결된 변수 묶음이 있다. 면적(Pixels_Areas–LogOfAreas–SigmoidOfAreas), 길이(X·Y 좌표 범위–Log_X_Index·Log_Y_Index), 밝기(평균 밝기–Luminosity_Index)는 서로 : 단조 관계, 강종 2열은 서로 반대 관계. 이러한 중복 으로 단조 관계 파생 변수는 만들지 않음, 강종은 1열로 합쳤다.


**주요 발견 사항**

1. 발견 사항 및 해석
: 현재 자료에서 K_Scatch·Stains는 대부분 A400, Z_Scratch는 대부분 A300에 속한다. 세 유형의 테스트 F1도 높았으나, 강종과 성능의 연관성만으로 높은 성능의 원인을 확정할 수는 없다.

2. 발견 사항 및 해석
: Bumps(A300 69%)와 Other_Faults(A400 60%)는 강종 분포가 섞여 있어 강종 신호만으로 구분되지 않는다. 이 두 유형 간 혼동이 전체 오분류의 47%를 차지했다.

3. 발견 사항 및 해석
: 면적·둘레·밝기 합 변수는 치우친 분포지만 로그 변환 변수가 데이터에 이미 있고 트리 모델을 쓰므로, 별도의 변환·제거 없이 사용할 수 있다.

### 6.2 데이터 전처리

**전처리 과정에서 고려한 사항**

- Train / Validation / Test 데이터 분할 방법
: 개발 1,552건과 테스트 389건을 층화 분할했다. 개발 데이터의 5-겹 교차검증으로 튜닝하고, 같은 fold의 OOF 확률로 단일 모델 4개와 앙상블 3개를 비교했다. 선택 후 테스트 성능을 
: 평가했으며 다른 후보의 테스트 점수는 참고값으로만 산출했다. 이후 중첩 교차검증과 반복 분할로 선택 과정의 안정성을 점검했다.

- 데이터 누수(Data Leakage) 방지 방법
: 테스트 데이터를 먼저 분리한 뒤, 파생 변수 결정·튜닝·Out-of-fold 예측·앙상블 선택·확률 보정 배율 탐색을 모두 개발 데이터로만 사용. 테스트는 최종 모델에 1회만 적용, 다른 후보의 
: 테스트 점수는 참고용으로만 기록해 선택에 반영하지 않았다. 학습과 예측이 같은 build_features 함수를 쓰도록 해 학습·운영 간 변환 불일치를 막았다.


- 주요 전처리 방법을 선택한 이유
: 데이터 타입 변환
: 원-핫 형태의 강종 2열은 Steel_Type(문자열 A300/A400)으로, 결함 7열은 Fault_Type(문자열)으로 병합한 뒤, 모델 입력 단계에서 각각 정수로 변환. 나머지 수치형 열은 원래   
: 자료형을 유지했다.


: 범주형 변수 처리
:  Steel_Type은 이진 변수라 A300=0, A400=1로 인코딩했다. 이 매핑 밖의 값이 들어오면 오류를 내도록 했다. Outside_Global_Index(0, 0.5, 1)는 순서가 있는 값이고 트리 모델은 
: 분기점으로 이를 구분할 수 있으므로 숫자형 그대로 사용했다.


: 학습. 검증. 테스트 분할 기준
: 별도 검증셋을 두지 않고 개발 80% / 테스트 20%로 층화 분할했다. 검증은 개발 데이터의 층화 5-겹 교차검증으로 대신해, 학습에 쓰는 데이터를 60%가 아닌 
: 80%로 늘렸다. 모든 모델은 같은 5개 fold(random_state=42)로 튜닝·비교했다.

### 8.1 최종 모델 선정

- **최종 모델:**

- **선정 이유:**
:  단일 모델 4개와 앙상블 3개 등 총 7개 후보를 개발 데이터 OOF 확률로 비교했다. 클래스별 배율 적용 후 OOF Macro F1이 0.8358로 가장 높은 상위 2개(LightGBM + Extra Trees)

- 성능: 7개 후보 중 보정 후 OOF Macro F1이 0.8358로 가장 높았다.
- 안정성 점검: 반복 분할에서 선택된 후보는 모두 앙상블이었으나 구성 모델 수는 달랐다. 이는 선택 절차의 경향을 보여주며, 특정 2개 모델 조합이 항상 최선이라는 근거는 아니다.

- 해석 가능성: 두 모델 모두 트리 계열이라 Permutation Importance로 변수 기여도를 확인할 수 있고, 예측 시 유형별 확률을 함께 제공한다.

### 10.2 한계점 및 개선 방향

- 데이터 측면의 한계
: 전체 표본이 1,941건으로 적다. 희소 유형은 Test에 Dirtiness 11건, Stains 14건뿐이라 성능 추정의 불확실성이 크다.
: 결함 이미지나 공정 기록 같은 외부 데이터를 활용하지 않았다.

- 모델 성능 및 일반화 측면의 한계
: Other_Faults는 여러 형태가 섞인 '기타' 유형이라 Bumps·Pastry와 특징이 겹친다. Test 오답의 81%가 이 세 유형 사이에서 발생했다.
: 여러 개선을 시도했지만 Other_Faults↔Bumps 오답은 37건에서 36건으로 거의 감소하지 않았다. 현재 측정 변수만으로는 두 유형을 구별할 정보가 부족하다.

- 추가로 시도하고 싶은 실험이나 개선 방법
: Other_Faults 여부를 먼저 이진분류하고, 나머지 결함만 6개 유형으로 분류하는 2단계 구조를 적용한다.
: 6개 유형별 판별 모델을 결합해 모두 '해당 없음'으로 판정한 결함을 Other_Faults로 분류하고, Other_Faults의 판정 기준은 따로 조정한다.
: 희소 유형 데이터를 추가로 확보하고 외부 데이터를 결합해 유형 간 겹침을 줄인다.
: 하이퍼파라미터를 고를 때도 중첩·반복 교차검증을 적용해 낙관적 편향을 줄인다.

### 10.3 프로젝트를 통해 배운 점

- 최원우: 프로젝트를 통해 배운 점: 적절한 파생 변수를 만드는 것은 쉽지 않은 작업임을 배웠다.

- 손규리: 데이터 전처리부터 모델링까지의 전 과정을 직접 수행하며, 분석 흐름을 익힐 수 있어 뜻깊었다. 여러 모델의 조합을 반복적으로 실험하고 결과를 비교하면서, 성능을 점진적으로 개선하는 방법을 배웠다.

- 강민정: 이번 모델링 프로젝트를 통해 단순히 정확도가 높은 모델을 만드는 것만으로는 충분하지 않다는 점을 배웠다. 처음에는 다양한 알고리즘을 적용하고 하이퍼파라미터를 조정하면 성능을 높일 수 있을 것이라고 생각했지만 실제로는 모델이나 파생변수를 추가하더라도 성능이 오히려 떨어지는 경우가 있었다.
이러한 과정을 통해 모델의 성능을 개선하기 위해서는 무작정 새로운 방법을 적용하기보다 데이터의 특성과 변수 간 관계를 먼저 이해하고 실험 결과를 객관적으로 비교하는 것이 중요하다는 것을 느꼈다.

- 황류경: 다양한 머신러닝 모델을 비교하고 성능 개선을 시도하면서 모델을 복잡하게 만든다고 성능이 무조건 오르지는 않는다는 것을 배웠다. 또한 교차검증을 통해 데이터 분할에 따라 성능이 달라질 수 있다는 점을 알게 되었다.

- 신유정:EDA에서 파악한 변수 특성을 조합해, 결함 유형 구분에 도움이 되는 파생변수를 설계해 볼 수 있었다. 다만 모델링 개선 과정에서 시도가 많아져 과정이 복잡해졌으므로, 다음 프로젝트에서는 범위를 한정하고 개선 방안을 미리 계획한 뒤 진행하고자 한다.
